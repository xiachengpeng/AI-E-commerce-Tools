# 选品研究助手整体方案（待审阅）

日期：2026-11-02。

状态：产品方案，不代表已实现或已获实施授权。本轮仅核对源码与编写文档；没有运行采集、收费 AI、正式数据保存、客户端安装或数据库迁移。

本文取代 2026-11-01 简化草案及此前两批流程图。那些图把商品链接、手填关键词当成主入口，缺少初始词准备、正式保留和广告粗筛等环节，不能作为实施依据。

## 一、目标与范围

让用户按业务问题操作：想研究什么、哪些商品值得留下、还缺什么、是否值得继续投入。系统负责准备搜索词、发现来源、提取已有信息、安排已授权任务、解释结果与定位下一动作。

普通用户不必先准备英文关键词或商品链接，不必理解十个后台步骤，不重复填写系统已经获得的资料。

本期只重整选品研究/SOP。复用现有本地客户端、AI 配置、数据源、项目与任务系统；不另建云服务、不改变后台管理平台，不自动投放广告或发布商品。

保留十个权威步骤及原有规则。减少导航、录入和任务编排负担，不减少真实证据要求。正式研究仍有人工判断，不能宣传成全程两三次点击。

## 三、先确定信息从哪里来

| 信息 | 由谁准备 | 不可混淆的边界 |
| --- | --- | --- |
| 研究范围 | 新项目由用户说明一次，已有项目读取已保存方向；AI 可辅助整理 | 没有任何方向时先确定范围，不随机编造用户意图 |
| 初始探索词 | AI 根据方向与目标市场准备，当地搜索表达附中文释义 | 只是探索建议，不是热度、广告存在或盈利证据 |
| 广告与商品链接 | 从当前渠道实际采集并读取关联落地页 | 链接缺失、分类页或重定向要显示待定位 |
| 商品身份 | 原广告与商品页对照；现有严格 AI 匹配或人工核实 | 成功抓取不等于同款；不一致和无法判断分别保留 |
| 广告素材与时间 | 当前来源实际记录、独立创意核对及历史观察 | 广告年龄和近期活跃不证明连续投放 |
| 商品需求查询词 | 从已核实商品名称、类型与原文准备 | 不把“租房”等探索方向直接拿去代表某个商品的需求 |
| 趋势结果 | 当前商品、市场、查询词绑定的两个真实时间窗口 | 相对热度不等于销量；两个窗口不自动互相确认 |
| Meta竞争、页面要素 | 从采集样本、广告原文及商品页提取草稿，附出处 | 样本广告数不等于相关广告主数，也不代表全部市场 |
| 成本与报价 | 已保存有效报价、适用费用资料；缺项由用户提供真实来源 | 商品页面售价不是采购成本；不假造供应商报价 |
| 后续探索词 | 经核实相关性的广告/商品原文，或有记录的复盘建议 | 原文扩词与复盘假设分别标记，来源扩词绑定引用与版本 |
| 测试数据 | 用户实际报表和明确来源 | 研究评分、计划预算都不是实际测试结果 |

## 四、完整主流程

研究方向与市场
→ 系统准备初始搜索方案
→ 用户审核本次搜索范围
→ 自动搜索广告、读取商品页、整理候选
→ 用户预览候选，明确保留/观察/淘汰
→ 对保留商品核实身份与广告证据
→ 系统准备商品研究方案并连续执行可自动处理的任务
→ 同页核对关键证据、补真实缺项
→ 自动重算有效评分
→ 用户明确决定去向
→ 按需准备测试、记录真实结果、复盘
→ 保存报告，并将新线索带回下一轮。

“查看候选”“初步资料摘要”“正式评分”“保存决定”是四种不同结果。资料不够也能看摘要，但不能因此跳过正式门槛。

### 1. 项目入口与首次准备

- 已有项目展示保存的方向、市场、资料进度和唯一主要操作；有进行中任务或待核对项时优先恢复，不重新从初始词开始。
- 新项目主要填写一句中文研究范围和目标市场；项目名称可由范围生成并允许修改，提交仍提供原创建接口要求的 title、direction、market。
- 每个项目只有一个目标市场；更换国家创建新项目，不能把原项目证据直接转用为新市场结论。
- AI 辅助扩写方向是草稿，用户可修改；不覆盖已输入内容。没有方向时提供可选择的研究范围示例，而不是要求英文关键词。
- 从当前设置只读检查文本 AI、已选广告采集方式、对应账户、项目规则和运行状态。只要求当前路径必需的配置；UI 模式不强迫配置 API，已有本地读取不强迫配置 Firecrawl。
- 设置缺失时直达主设置的对应编辑器，保存后回到原任务；不再新增第二套凭据表单。读取设置不发起收费连接测试。

### 2. 系统准备搜索方案

- 用户点击“准备搜索方案”，授权一次范围明确的初始词 AI 请求；页面打开不自动产生新费用。
- 复用现有 suggest：按市场输出当地常见的品类、功能、人群、痛点、场景表达及中文释义。单词可以作为入口，不强凑组合，不凭空造品牌。
- 现有最多 30 个初始建议保持后端上限；拟议 UI 先推荐最多 3 个进入本次方案，其余可展开。3 是减少首批任务的产品提案，不改变服务端规则。
- 显示每个实际词、中文含义、建议缘由和待审核状态。用户可以删词、改词或展开备选。
- 本次只搜索审核方案列出的词；项目里其他以前审核的词不能因为一个批量按钮被顺带执行。
- 显示当前账户/采集方式、本次词数、调用上限；可可靠取得价格时才显示估算金额。
- “按这组词开始搜索”代表用户审核这组可见实际词及范围，底层仍逐项调用原审核命令。隐藏或未审核的建议不入队。
- 空方案不可提交；超过项目批量或预算上限时显示可执行子集，不能静默截断后把剩余词说成已搜索。

### 3. 自动发现广告与商品

- 对审核通过的本次词运行既有 scan/scan_all；使用实际已选 UI/API 模式，不静默切换账户或付费方案。
- 复用已有去重和来源绑定；搜索成功后按现有上限排队本地商品页读取，不重复已有成功任务。
- 显示搜索中、页面读取中、局部成功、零结果、来源受阻等真实状态。没有记录条数不解释为 0。
- 候选集中展示广告、商品页、已保存名称、图片、来源、套餐/价格范围与未知项；广告主名称不冒充商品名。
- 同一精确商品来源可去重展示，不把不同卖家、不同套餐或相似图片自动合并；原始来源与历史保留。
- 初始版本不对所有候选自动执行收费深度研究。候选排序解释其依据，不能显示为“已通过”。

### 4. 预览、初筛与正式保留

- 候选可直接预览，不先要求写结论。对照广告与商品页时仍有一致、不一致、无法判断三种结果。
- “保留并深入”“先观察”“淘汰线索”均需明确选择并保存实际理由；理由可提供来源明确的草稿/选项，用户作出选择，不能默认提交。
- 保存 retained 后才允许原 focus_product 命令，二者串行且分别有回执；失败保留中间状态，不伪造已深入。
- 选择预览不修改 triage；保留不等于身份匹配、粗筛通过或测试资格。
- 观察/淘汰保留证据与理由，可恢复/纠正。身份不一致不自动淘汰；triage 与同款结果独立。
- 身份有效时准备广告粗筛核对：实际广告年龄、当前投放观察、独立活跃创意及各自依据。没有素材不补空素材，不由年龄推断持续投放。
- AI 已严格匹配时明确标识方法，保留人工复核；无法匹配时给对照任务，不自动替用户确认。

### 5. 自动准备商品研究方案

- 对正式保留的当前商品，复用已核实原文准备商品级 Trends 查询词，附中文释义及原文依据；不会直接照抄初始探索词。
- 有效的已确认查询可复用；冲突的旧词或身份变化不能盲用。两个窗口固定使用同一个已确认词、市场和当前身份。
- 在同一个核对区展示商品、广告粗筛、实际趋势查询词与本次调用范围，用户处理依赖项后继续；身份需先修正时允许分次保存，不承诺永远一次核对完成。
- 自动准备 Meta 样本竞争分析与广告/页面要素草稿，逐项附来源、引用、时间和未知字段。可独立准备的工作不因另一来源受阻全部停下。
- 当前已有自动采集主要为 Meta 广告、商品页和 Trends；其他渠道不假装已有全自动连接器。按项目规则列出可选/推荐/必需渠道，缺少能力或来源时说明如何补。
- 初步摘要随资料就地更新：观察到什么、哪里未核对、哪些资料缺失、是否值得继续核查。它不产生完整评分、测试资格或已保存去向。

### 6. 集中核对证据与真实成本

- 一页处理服务端返回的实际缺项，原始资料默认折叠并可随时查看，不让用户重填查询词、来源 URL 和观察时间。
- Meta、Trends 12m、Trends 5y、页面要素分别有明确选择；自动草稿不会标记为人工已确认。
- 保存多项时逐项串行，显示每项成功与剩余项；遇到版本冲突或未知回执立即停下恢复，已成功项不重复保存。
- 成本分为“已知可复用”“本商品还缺”“详细费用”；优先带入已有有效值，来源、适用范围与有效期均可查看。
- 经济模型 18 个必需字段：unit_price、quantity、aov、goods_cost、shipping、packaging、tax、ad_cost、payment_percent、payment_fixed、reserve_percent、weight_kg、quote_source、quote_date、quote_confirmed、logistics_risk、compliance_risk、ip_risk。
- 18 是服务端必需字段数，不等于用户每次手填 18 项；不完整时只追问实际缺项。多件订单还要有组合依据，认证按条件核实。
- 售价、套餐、件数、客单价、成本按同一订单口径；不擅取最低展示价、不把售价乘件数强写为实际客单价。
- 当前正式成本统一 USD；其他币种须明确换算依据与口径，未知费用不填 0。广告成本假设标为假设，不冒充实际投放数据。
- 报价来源与日期必须满足现有接口及有效期要求；尺寸、体积重除数、认证未知时保持未知。首版不承诺自动寻找供应商或导入任意报价文件。

### 7. 评分、决定和报告

- 根据权威缺项判断资料是否齐备；齐备时自动调用原 evaluate，展示有效评分与硬门槛原因。证据变化时重新检查，不显示过期分数为当前结果。
- 未齐备只显示初步摘要和具体缺项，可继续观察；不能为了给用户“一个分数”凑齐数据。
- 展示测试候选、备选、观察、淘汰的适用条件及有依据的建议理由；最终去向和理由必须由用户明确提交。
- 完整评分不自动保存决定；测试候选也不代表批准投放。原决策门槛不变。
- 报告含当前阶段、证据、缺口、来源、建议与已保存决定；不齐备也可导出标明边界的研究记录。
- 营销工具交接为可选明确操作，保持项目/商品/来源版本绑定，不自动覆盖用户在营销模块的编辑。

### 8. 测试、复盘和下一轮

- 进入测试候选后，程序可准备有依据的测试计划草稿；用户明确预算、周期、目标 CPA、停止线并批准保存。
- 保存计划不创建广告、不付款、不自动投放；实际执行继续由用户在相应业务系统完成。
- 实际结果按报表来源、周期、花费、点击、订单等填写并确认；无真实数据时不编造结果。修订与作废追加历史，统计周期和轮次继续校验。
- 测试候选没有有效已确认结果时不产生“测试完成”的复盘。观察/淘汰/备选可走研究复盘，标签区分。
- 系统整理结论与教训草稿，用户保存后入历史；原文扩词与复盘建议分别标注来源性质。
- 下一轮搜索词重新审核后才搜索，遵守深度、数量、预算和来源有效性；不无限自动循环。

## 五、用户界面与人工工作量

界面聚焦五处工作区：项目/方向、搜索方案、候选发现、商品研究与集中核对、结论与测试复盘。它们是展示分区，不替代后台步骤；主要状态变化在原地显示。

已有项目优先展示“继续当前任务”，不是每次从头。每个状态只有一个主要下一操作；保存回执同时说明保存了什么、是否达到门槛、还缺什么。

| 人工工作 | 何时发生 | 程序如何减少负担 |
| --- | --- | --- |
| 确定方向和市场 | 新项目；已有项目不重复 | 方向辅助整理、记住有效范围 |
| 审核实际搜索方案 | 新词、扩词或范围变化 | AI 准备词与中文解释，批量审核可见范围 |
| 候选取舍及理由 | 正式保留/观察/淘汰 | 同页预览来源，原因选项/草稿辅助 |
| 身份、广告粗筛与商品查询词核对 | 相应证据尚未满足 | 有来源的对照与自动检查，不从空表开始 |
| 渠道证据、成本和风险 | 当前商品实际缺项 | 已有有效信息带入，只问未知 |
| 最终去向及理由 | 形成正式研究结论或选择观察 | 程序整理建议，用户明确保存 |
| 测试计划、结果和复盘 | 选择测试/下一轮时 | 可选后续，不强迫所有商品走完 |

“准备方案、批准搜索、保留研究”是主要提交环节，不等于三个点击完成研究。审核多个词、保存理由、创意独立性、成本输入均按真实动作计数。撤回此前固定 2/3/10/11 次完成研究的承诺。

验收同时记录页面切换、输入字段、主动点击、独立判断、等待/恢复次数。对既有项目、新建项目、无报价、来源失败分别实测。目标是零必需手写英文词、零必需手找商品链接、零重复填写已有有效信息，而不是强行规定每个项目同样步数。

## 六、自动推进、费用和恢复

- 所有自动链路都有持久运行记录，绑定项目、方向、市场、词清单/商品、来源版本、规则及当前服务账户/模型配置。
- 准备搜索方案的 AI 授权、公开搜索授权、选定商品的深入研究授权分开记录；可在业务页面合并呈现，但不能用前一阶段无限授权后一阶段。
- 拟议默认一次初始词准备、最多 3 个首批搜索词、同时深入 1 个明确保留商品；都受当前项目/服务预算更严格约束。自动扩词搜索默认不启用。
- 只读状态检查与查看页面不触发外部付费请求。服务运行就绪不等于允许消费。
- 每次派发原子检查预算和运行围栏，复用现有计量及网络回执，不重复扣用量。未知费用显示调用上限，不承诺固定金额。
- 来源、查询词、方向、规则、账户或模型有相关变化时暂停受影响任务；不静默切换账户/模式。正常任务保存造成的版本增长不应把整条运行误判为过期。
- 失败只恢复失败项。结果不确定时先查询原任务/命令回执；没有证据证明可安全再发时等待人工处理。
- 完成词重搜仍绑定 rescan_of，阻塞恢复绑定对应 retry_action_id；部分成功和历史不清空。
- 单次运行可暂停新任务派发，后台进程仍保持现行运行策略；已发出请求可能完成，不能承诺“暂停即零费用”。
- 关闭页面不丢已记录任务；退出整个客户端会停止本地执行，重开后按既有恢复规则继续可恢复任务，不保证所有外部请求可无条件重发。
- 草稿按项目、商品、来源和编辑器生命周期隔离；切换候选后的迟到结果不得覆盖新对象。

## 七、必须验收的异常分支

| 情况 | 应有行为 |
| --- | --- |
| 无方向/市场 | 定位一次性的范围准备，不要求关键词或链接 |
| AI 未配置、失败或无有效词 | 保留方向，说明设置/失败原因，不伪造词；手动方式仅辅助 |
| 改方向/改词/改账户后旧结果回来 | 历史保留，不覆盖当前方案、不自动搜索 |
| 可执行词为空、超预算或已搜完 | 不提交空批次；说明可执行范围/显式重搜入口 |
| 零广告/采集受限/验证页面 | 区分零结果与读取失败，不自动换词、换来源或认为没有市场 |
| 部分页面失败/分类页/重定向 | 保留其他结果，绑定原来源补读或修正具体商品 |
| 不一致/无法判断/素材不足 | 不自动确认、不自动淘汰，保留修正路径并阻止不合法扩词 |
| 未保存保留理由就要求深入 | 停在原地完成明确初筛保存，不绕开 focus_product |
| 缺一窗口、词不一致或趋势数据不足 | 对应项保持未知，保存其他项，不完整评分 |
| 同图不同卖家/套餐与币种歧义 | 保留卖家与订单口径，不自动合并或选低价 |
| 无报价、过期报价、认证未知 | 初步摘要可看；正式缺项明确，不补假值 |
| 双击、刷新、崩溃、断网、409 | 稳定命令与任务身份，恢复已提交回执，不重复收费 |
| 暂停、取消、后台未就绪 | 显示真实执行状态，不宣称已发请求消失或仍在离线执行 |
| 旧项目/过期决定/观察或淘汰后恢复 | 原焦点与当前缺项正确恢复，历史不改写 |
| 无真实测试结果/重叠周期/结果修订 | 保留原校验；区分研究复盘与测试复盘 |
| 跨模块、主设置与移动/大字号 | 共享导航不回退，编辑器唯一，内容不溢出且焦点可操作 |
