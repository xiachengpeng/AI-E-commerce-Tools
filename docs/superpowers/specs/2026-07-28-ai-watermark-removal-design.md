# AI 消除功能设计

## 目标

为本地电商工具新增“AI 消除”模块。用户上传一张有权编辑的图片，在原图上创建一个或多个矩形选区，然后调用已配置的图片 AI，仅重建选区覆盖的水印区域。处理完成后，用户可以对比、下载并通过全局历史恢复查看结果。

第一版限定为单图、多个矩形选区和水印消除，不包含批量处理、画笔蒙版、自动水印检测或通用对象移除。

## 用户流程

侧边栏新增“AI 消除”入口，页面包含三个状态：

1. 上传态：用户上传一张 JPG、PNG 或 WebP 图片。
2. 编辑态：图片显示在可缩放画布中。用户可以拖拽创建多个矩形，移动或缩放已有矩形，选中后删除，或清空全部选区。
3. 结果态：页面展示原图与结果图对比，并提供下载、重新消除和更换图片操作。

“AI 消除”按钮仅在图片有效、至少存在一个有效矩形且当前没有请求执行时可用。重新消除保留原图，用户可以重新绘制选区。更换图片会清空上一张图片及其选区。

页面提示用户仅上传和处理自己拥有或获准编辑的图片。

## 选区与蒙版

前端以原图为坐标系，将每个矩形保存为 `x`、`y`、`width`、`height` 四个 0–1 范围的归一化数值。矩形必须具有正宽高，并完全位于图片范围内。这样画布缩放不会改变选区的实际位置。

提交时，前端创建一张与原图像素尺寸完全一致的 PNG 蒙版：

- 黑色表示必须保留的区域。
- 白色表示允许 AI 重建的区域。
- 多个矩形的白色区域合并到同一蒙版中。

请求同时携带归一化矩形列表，供后端独立验证蒙版覆盖范围和记录历史。第一版不在矩形边缘添加羽化；让图片模型结合原图上下文完成自然过渡，避免前端预先改变实际编辑范围。

## 前端结构

新增独立的页面区块、样式和 JavaScript 模块，遵循现有 `index.html`、功能模块脚本和全局 `switchMainTab` 路由模式。

前端模块负责：

- 图片读取、格式和基础状态管理。
- 原图画布缩放与矩形创建、移动、缩放、选择、删除。
- 坐标归一化及同尺寸黑白蒙版生成。
- 请求状态、错误提示和结果渲染。
- 原图与结果图对比、结果下载。
- 成功后写入全局历史，以及从历史记录恢复只读对比状态。

失败时不得清空原图或矩形选区。用户可以修正选区或直接重试。

## API 与后端服务

新增 `POST /api/watermark-removal`。请求体包含：

- `image_data`：原图 data URL。
- `mask_data`：PNG 蒙版 data URL。
- `filename`：原文件名。
- `regions`：归一化矩形数组。

后端服务按以下顺序执行：

1. 使用共享图片校验逻辑解码并验证原图。
2. 验证蒙版是 PNG 图片，且像素尺寸与原图完全一致。
3. 验证至少有一个矩形，所有坐标为有限数值、宽高为正且没有越界。
4. 验证蒙版包含可编辑白色像素，且白色区域与矩形列表表达的区域一致。允许画布栅格化产生不超过一个像素的边界取整差异。
5. 通过现有 `image` 能力路由调用当前配置的 Gemini、Vertex 或兼容图片提供商。
6. 校验模型返回有效图片，且结果像素尺寸与原图完全一致。
7. 保存原图、蒙版和结果图，并返回可访问 URL 和处理元数据。

接口成功响应包含处理记录 ID、原图 URL、蒙版 URL、结果 URL、原文件名、宽度、高度、矩形列表和创建时间。

## AI 调用

模型输入包含原图、黑白蒙版和约束提示词。提示词要求：

- 仅重建白色蒙版覆盖区域。
- 使用相邻区域的纹理、结构、光照和颜色自然补全。
- 保持黑色蒙版区域逐像素不变。
- 不添加文字、标识、图案或其他新元素。
- 返回与原图尺寸相同的单张完整图片。

调用必须经过后端现有图片能力代理和路由，不允许浏览器直接访问模型。日志只记录能力、提供商、模型、耗时、重试次数和已清洗的错误信息，不记录 API 密钥、完整 base64 图片、蒙版或完整模型响应。

如果模型未返回图片或返回尺寸变化的图片，后端明确失败，不通过拉伸或裁剪掩盖异常。

## 文件与历史

生成文件保存到 `backend/static/outputs/watermark-removal/` 下按处理记录隔离的目录。该目录属于本地生成资源，继续遵循项目现有的 Git 忽略规则。

成功处理后，前端调用现有历史写入流程，模块键使用 `watermark-removal`。历史数据记录：

- 原文件名、宽度和高度。
- 原图 URL、蒙版 URL 和结果 URL。
- 归一化矩形列表。
- 处理记录 ID 和时间。

全局历史面板新增“AI 消除”分类。点击历史记录恢复原图与结果对比以及矩形元数据，但不会自动再次调用 AI。历史恢复后，用户可以下载结果或以原图为基础重新编辑并发起新请求。

删除历史记录仅删除历史数据库记录；静态生成文件遵循项目现有资源保留策略，不在本功能中新增级联删除。

## 错误处理

前端以中文区分以下错误：

- 原图或蒙版格式无效。
- 图片过大或尺寸超限。
- 没有有效选区，或选区坐标越界。
- 蒙版尺寸或内容与选区不一致。
- 图片 AI 未配置。
- 模型未返回图片。
- 结果尺寸与原图不一致。
- 网络中断或上游服务失败。

请求执行期间禁用上传替换、选区编辑和提交按钮，避免同一页面状态重复提交。请求结束后恢复编辑能力；任何失败都保留原图和全部选区。

## 测试

后端测试覆盖：

- 原图、蒙版和矩形请求校验。
- 空选区、非有限数字、零面积和越界矩形。
- 蒙版与原图尺寸不一致。
- 蒙版无白色区域或与矩形列表不一致。
- 通过图片能力路由调用 AI。
- 模型无图片响应或结果尺寸不一致。
- 成功响应、文件落盘和序列化数据。
- 历史模块键可被保存、读取和删除。

前端 Node 测试覆盖：

- 画布坐标与归一化坐标相互转换。
- 多个矩形合成正确蒙版。
- 无选区、处理中和有效选区时的按钮状态。
- 失败后原图和选区状态保持。
- 历史记录到页面状态的恢复映射。

验收时运行完整后端测试、相关前端 Node 测试和新增脚本的语法检查，并在本地浏览器完成一次 JPG 或 PNG 上传、创建两个选区、AI 消除、结果下载和历史恢复流程。

## 验收标准

- 用户能在单张图片上创建、编辑和删除多个矩形选区。
- AI 仅针对选区消除水印，输出图片尺寸与原图一致。
- 处理失败不会清空原图或选区。
- 成功结果支持前后对比和下载。
- 成功记录可从全局历史恢复查看。
- 所有 AI 调用经过后端配置的图片能力路由，敏感数据不进入普通日志。
