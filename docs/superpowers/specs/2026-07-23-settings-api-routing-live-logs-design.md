# 设置页、AI 能力路由与实时日志设计

## 1. 目标

在现有 AI 电商工具箱首页增加“设置”入口，并提供一个独立设置页面，用于：

- 管理多个 AI API 线路。
- 支持 Gemini、Vertex AI 和 OpenAI Compatible 三种协议。
- 分别为文本 AI 和图片 AI 选择线路与模型。
- 保存后立即生效，并在应用重启后保持配置。
- 查看经过脱敏的应用实时日志。
- 测试线路连接，提前发现鉴权、模型、超时或协议兼容问题。

本功能服务于本地单用户应用。第一版不引入账号、权限、多设备同步、费用统计、自动故障转移或长期日志归档。

## 2. 已确认的产品决策

- API 按“能力”切换，而不是全局切换或按业务模块切换。
- 能力分为 `text` 和 `image`。
- 切换后无需重启，下一次请求立即使用新线路。
- 配置持久化到现有 SQLite。
- 支持新增、编辑、删除、连接测试、启用和停用线路。
- 日志展示应用级日志，包括 AI、爬虫、图片处理、历史记录和前端任务日志。
- 设置页采用双栏运维台布局：左侧管理能力路由和 API 线路，右侧持续显示实时日志。
- `.env` 仅作为首次启动的默认配置来源和故障恢复手段。
- OpenAI Compatible 图片线路另有持久化的文生图/图生图模式：文生图调用 `/v1/images/generations`，图生图调用 `/v1/images/edits` 并上传参考图；旧线路默认图生图。详细协议约束见 `2026-08-11-openai-image-generation-mode-design.md`。

## 3. 信息架构与页面布局

### 3.1 导航入口

在首页左侧导航底部新增“设置”按钮，与“历史”入口放在同一区域。点击后通过现有 `switchMainTab()` 机制进入设置视图，并记录为当前主标签页。

### 3.2 设置页

设置页采用左右双栏布局。

左栏包含：

1. 能力路由卡片。
2. API 线路列表。
3. 新增或编辑线路表单。

右栏固定为实时日志终端。用户可以在切换线路或执行连接测试时同步观察日志。

窄屏下允许上下排列：配置区域在上，日志区域在下。功能和字段保持一致，不单独设计另一套交互。

### 3.3 能力路由

提供两个独立绑定：

- 文本 AI：选择支持文本能力的已启用线路和该线路的文本模型。
- 图片 AI：选择支持图片能力的已启用线路和该线路的图片模型。

保存绑定后立即生效。正在执行的请求继续使用请求开始时取得的配置；之后发起的请求使用新配置。

### 3.4 API 线路列表

列表展示：

- 线路名称。
- 协议类型。
- 支持能力。
- 启停状态。
- 最近一次连接测试状态。
- 编辑、测试、启停和删除操作。

正在被文本或图片能力绑定的线路不能停用或删除。界面和后端都必须执行此约束，并提示用户先切换能力绑定。

### 3.5 线路表单

通用字段：

- 线路名称。
- 协议类型：`gemini`、`vertex`、`openai_compatible`。
- Base URL。
- API Key。
- 文本模型名称。
- 图片模型名称。
- 支持能力：文本、图片或两者。
- 请求超时。
- 最大重试次数。
- 启用状态。

Vertex AI 额外字段：

- Project ID。
- Location。
- 凭据文件路径。

编辑时 API Key 和其他敏感凭据不回传原值。表单留空表示保留已有值；显式输入新值才进行覆盖。

## 4. 后端架构

### 4.1 总体调用链

```text
业务服务
  → AIRouter(text | image)
  → AIConfigService
  → 当前能力绑定及线路快照
  → GeminiAdapter | VertexAdapter | OpenAICompatibleAdapter
  → 外部 API
```

业务层不再自行决定 Provider、Base URL、密钥或模型。提示词构建、业务结果解析和历史记录逻辑保持在现有业务 Service 中。

### 4.2 AIConfigService

职责：

- API 线路的创建、读取、更新、删除、启用和停用。
- 文本与图片能力绑定管理。
- 敏感字段写入与掩码读取。
- 线路配置校验。
- 首次启动时从 `.env` 导入默认线路。
- 为单次 AI 请求返回不可变配置快照。

配置更新使用数据库事务，避免能力绑定和线路配置出现部分写入。

### 4.3 AIRouter

职责：

- 接收能力类型和统一 AI 请求。
- 获取当前能力绑定及线路快照。
- 校验线路已启用并支持目标能力。
- 选择对应 Provider Adapter。
- 记录开始、重试、成功或失败日志。
- 返回统一响应。

若目标能力没有可用线路，返回明确的配置错误，引导用户前往设置页。

### 4.4 Provider Adapter

定义统一适配器接口，使业务层不依赖供应商协议。

适配器包括：

- `GeminiAdapter`：Gemini API Key 模式。
- `VertexAdapter`：现有 Vertex AI 模式。
- `OpenAICompatibleAdapter`：自定义 Base URL 与 API Key。

统一输入需要支持：

- 文本内容。
- 图片输入。
- 响应格式要求。
- 图片比例和尺寸等现有生成参数。

统一输出保持与当前业务所需结构兼容，包括文本结果和图片 Base64/媒体类型数据。

OpenAI Compatible 适配器第一版调用 `POST /v1/chat/completions` 处理文本和多模态文本响应，调用 `POST /v1/images/generations` 处理图片生成。用户填写的 Base URL 是服务根地址；后端统一去除尾部 `/` 后拼接接口路径。线路声明支持图片能力但图片接口不兼容时，连接测试必须返回明确结果，不能把线路标记为可用。

### 4.5 客户端生命周期

客户端按线路 ID 和配置版本缓存。修改 Base URL、凭据、协议或模型后，使对应缓存失效。

每次请求在开始时取得配置快照：

- 已开始请求不受后续设置修改影响。
- 新请求立即使用新配置。
- 不需要重启 FastAPI。

## 5. 数据模型

### 5.1 AI API 线路

新增 `ai_provider_configs` 表，包含：

- `id`
- `name`
- `protocol`
- `base_url`
- `api_key`
- `vertex_project_id`
- `vertex_location`
- `vertex_key_path`
- `text_model`
- `image_model`
- `supports_text`
- `supports_image`
- `timeout_seconds`
- `max_retries`
- `enabled`
- `last_test_status`
- `last_test_message`
- `last_tested_at`
- `created_at`
- `updated_at`
- `config_version`

API Key 延续本地应用的敏感数据模型，存放在不会提交 Git 的本地 SQLite 中。任何读取接口不得返回原值。

### 5.2 能力绑定

新增 `ai_capability_bindings` 表：

- `capability`，唯一值为 `text` 或 `image`。
- `provider_config_id`
- `updated_at`

模型名称属于线路配置。能力绑定同时选中线路和该线路对应的模型字段。

### 5.3 首次导入

启动时若不存在任何 AI 线路：

1. 读取现有 `.env`。
2. 根据 `AI_PROVIDER` 创建 Gemini 或 Vertex 默认线路。
3. 导入 `FRONTEND_TEXT_MODEL`、`FRONTEND_IMAGE_MODEL` 和相关凭据配置。
4. 将支持的能力绑定到默认线路。

数据库已有线路后，不再从 `.env` 自动覆盖用户设置。

## 6. API 设计

设置后端接口使用 `/api/settings` 命名空间：

- `GET /api/settings/ai/providers`
- `POST /api/settings/ai/providers`
- `PUT /api/settings/ai/providers/{id}`
- `DELETE /api/settings/ai/providers/{id}`
- `POST /api/settings/ai/providers/{id}/test`
- `POST /api/settings/ai/providers/{id}/enable`
- `POST /api/settings/ai/providers/{id}/disable`
- `GET /api/settings/ai/bindings`
- `PUT /api/settings/ai/bindings/{capability}`
- `GET /api/settings/logs/recent`
- `GET /api/settings/logs/stream`

创建或编辑线路时执行字段和协议组合校验。读取线路时敏感字段只返回：

- 掩码，例如 `sk-****9X2a`。
- `has_api_key` 布尔值。

连接测试使用未保存的表单配置或已保存线路均可，但测试本身不得改变能力绑定。

## 7. 实时日志

### 7.1 AppLogService

新增应用日志服务，统一接收结构化日志事件。日志事件至少包含：

- 时间。
- 级别：debug、info、warning、error、success。
- 来源：frontend、ai、crawler、image、history、system。
- 能力：text、image 或空。
- 线路和模型的非敏感名称。
- 事件摘要。
- 耗时。
- 重试次数。
- 简短错误信息。

内存使用固定长度队列，仅保留最近 200 条。应用重启后日志清空，不写入 SQLite。

### 7.2 SSE

设置页打开后：

1. 获取最近日志快照。
2. 建立 SSE 连接。
3. 持续追加新的日志事件。

SSE 断开后浏览器自动重连。日志连接故障不得影响 AI 请求或其他业务功能。

### 7.3 日志界面

支持：

- 按级别过滤。
- 按来源过滤。
- 按能力过滤。
- 自动滚动开关。
- 暂停和继续显示。
- 清除当前浏览器显示。
- 复制当前可见日志。
- SSE 连接状态提示。

“清屏”仅修改当前页面，不清除服务端缓冲。

### 7.4 脱敏

日志服务在写入缓冲和推送之前统一清洗。禁止记录：

- API Key。
- Authorization Header。
- Vertex 凭据内容。
- 图片 Base64。
- 完整 Prompt。
- 完整第三方响应。

允许记录安全摘要、长度、模型名称、状态码、错误类型和经过截断的错误信息。

## 8. 错误处理

- 当前线路失败时，仅按线路配置重试，不自动切换供应商。
- 鉴权失败、模型不存在、限流、超时和协议不兼容需要映射为可理解的错误。
- 连接测试结果保存最近状态和时间，但不能自动启用线路。
- Base URL 仅接受 `http` 或 `https`，并拒绝包含用户名密码的 URL。
- 更新或删除不存在的线路返回明确的 404。
- 删除或停用已绑定线路返回冲突错误。
- 能力和线路不匹配时，保存绑定失败。
- 设置保存失败时，界面保留用户填写内容并展示错误，不回滚到空表单。
- SSE 故障只显示“日志连接中断”，不阻止配置操作。

## 9. 安全边界

应用仍定位为仅监听本机的单用户工具。第一版不增加身份认证系统。

必须保证：

- 敏感凭据不进入前端全局变量。
- 普通配置接口不返回敏感原值。
- 日志和异常响应不泄露敏感字段。
- 本地数据库、`.env` 和生成资产继续被 Git 忽略。
- 浏览器只向本地 FastAPI 发送设置请求，第三方 API 调用仍全部经过后端。

## 10. 兼容性与迁移

- 保留现有 `/config` 接口，但返回当前能力绑定所对应的公开线路和模型信息，不返回凭据。
- 前端现有 `AI_PROVIDER`、`TEXT_MODEL` 和 `IMAGE_MODEL` 逐步改为只用于展示或请求提示，不再决定真正的后端凭据。
- 所有 AI 调用最终经过 `AIRouter`，避免通用代理与业务接口使用不同配置源。
- 现有业务提示词、解析、评分和历史记录格式不在本次范围内修改。
- 现有 Gemini/Vertex 用户在首次启动时自动获得等价默认配置。

## 11. 测试策略

### 11.1 后端

- 线路 CRUD、协议字段校验和敏感字段掩码。
- 编辑时空密钥保留原值。
- 已绑定线路禁止删除或停用。
- 文本和图片能力独立绑定。
- 配置切换后新请求立即采用新线路。
- 请求配置快照不受执行中修改影响。
- 三种适配器的请求和响应转换。
- 文本、图片和多模态输入。
- 连接测试的成功、鉴权失败、模型不存在、限流、超时和协议不兼容。
- 重试次数来自线路配置，且失败时不自动切换。
- `.env` 首次导入及后续启动不覆盖。
- 日志脱敏、200 条上限和订阅发布。
- SSE 初始快照、持续推送和客户端断开清理。
- 现有 97 项后端测试全部回归。

### 11.2 前端

- 设置导航与标签页状态。
- 双栏布局和窄屏排列。
- 线路新增、编辑、测试、启停和删除状态。
- 编辑线路时密钥留空语义。
- 能力下拉仅显示兼容线路。
- 保存成功、冲突和网络错误反馈。
- 日志过滤、暂停、自动滚动、清屏和复制。
- SSE 断线状态与自动重连。
- 所有 JavaScript 文件通过语法检查。

## 12. 验收标准

功能完成后应满足：

1. 用户可以从首页进入设置页。
2. 用户可以管理 Gemini、Vertex 和 OpenAI Compatible 线路。
3. 文本与图片能力可以绑定不同线路和模型。
4. 保存绑定后无需重启，下一次调用立即使用新配置。
5. 重启应用后配置仍然存在。
6. 正在使用的线路不能被停用或删除。
7. 用户可以在保存前或保存后测试连接。
8. 设置页可以持续显示最近及实时应用日志。
9. 日志和 API 响应不泄露凭据、图片 Base64 或完整提示词。
10. 现有竞品分析、Listing、广告、翻译、详情页和方图重绘功能继续通过回归测试。
