# 详情页 AI 帮写产品名称设计

## 目标

改进详情页“核心卖点”区域的 AI 帮写流程，使产品名称成为 AI 识图和卖点生成的一部分：

- 产品名称为空时，AI 根据上传的产品图识别产品，生成符合当前输出语言的产品名称，并自动回填产品名称输入框。
- 产品名称非空时，AI 同时参考上传图片和用户输入的名称生成核心卖点。
- 用户已输入的产品名称不得被 AI 返回值覆盖。
- 保持现有图片、产品事实和禁用声明上下文不变。

## 交互流程

1. 用户上传一张主图，可选上传角度或细节图。
2. 用户可选填产品名称。
3. 用户点击“AI 帮写”。
4. 前端读取产品名称、当前输出语言、产品事实、禁用声明和最多三张产品图。
5. AI 单次返回结构化结果：
   - `product_name`：符合当前输出语言的简洁电商产品名称。
   - `selling_points`：现有核心卖点区域所需的完整产品简报。
6. 前端解析结果并更新页面：
   - 点击前名称为空：回填 `product_name`。
   - 点击前名称非空：保留用户输入。
   - 始终用 `selling_points` 更新核心卖点文本框。

## AI 提示词与响应格式

`buildSellingPointsExtractionPrompt` 增加当前输出语言参数，并明确要求只返回 JSON：

```json
{
  "product_name": "符合当前输出语言的产品名称",
  "selling_points": "包含产品类型、已知事实、核心卖点、目标用户、使用场景和风险声明的文本"
}
```

名称为空时，提示 AI 以图片证据为准识别产品并命名。名称非空时，将用户名称作为已确认上下文，同时仍以图片作为视觉事实来源。

## 解析与兼容

新增独立的纯函数解析 AI 返回内容，便于单元测试：

- 首选解析严格 JSON。
- 兼容包裹在 Markdown 代码块中的 JSON。
- 兼容中转 API 或旧模型返回的普通文本：
  - 尝试从 `Product name:`、`产品名称：`等首行标签提取名称。
  - 完整普通文本继续作为 `selling_points` 使用。
- 解析不到名称时不修改产品名称输入框。
- 没有可用卖点内容时按生成失败处理，保留原输入内容。

## 状态与错误处理

- 请求期间沿用现有按钮禁用和加载状态。
- AI 返回有效卖点后显示成功提示。
- 名称为空但未能解析出名称时，卖点仍正常回填，不阻断成功流程。
- 请求失败或响应无有效卖点时，保留现有产品名称和卖点内容，显示错误提示并记录详细日志。
- 日志记录是否回填了名称，但不记录图片数据。

## 测试

前端测试覆盖：

1. 空名称提示词要求根据图片识别，并按当前输出语言返回名称。
2. 已输入名称会进入提示词，并明确参与图片分析。
3. 严格 JSON 和 Markdown JSON 代码块均可解析。
4. 中文与英文普通文本均可提取名称并保留完整卖点。
5. 名称为空时回填 AI 名称。
6. 名称非空时不覆盖用户输入。
7. 无有效卖点时保持原页面内容并进入错误分支。

## 范围

本次只修改详情页“AI 帮写”流程及其前端测试，不新增后端接口、不改变 AI 路由设置，也不调整详情页其他生成模块。
