# 详情页模块级文案开关设计

## 目标

在每个详情页模块卡片的“张数”控制下增加“包含文案：是 / 否”设置，让不同模块独立决定生成图中是否新增营销文案。

## 交互

- 设置只在模块启用后显示。
- 默认选择“是”，保持当前生成行为。
- 用户可以对每个模块单独选择“是”或“否”。
- 一个模块设置为“否”时，该模块生成的所有张数都使用无文案模式。
- 切换设置不得触发模块启用/停用，也不得改变模块张数。

## 数据模型

为每个模块增加 `includeText: boolean`：

- `true`：允许按现有规则生成标题、副标题和最多三个卖点或信息点。
- `false`：禁止新增任何可见文案。
- `MODULES_CONFIG` 中所有模块默认 `true`。
- `buildStrategyTasks()` 将模块值复制到每个图片任务。
- 重绘沿用任务中的 `includeText`，不重新读取其他模块的状态。
- 历史快照保存该字段；旧历史缺少字段时按 `true` 处理。

## 无文案模式

当 `includeText` 为 `false` 时，最终图片不得新增：

- 标题、副标题、卖点、说明文字。
- 参数、尺寸、对比表、步骤标签。
- 徽章、水印、促销贴纸。
- 任何额外字母、数字、符号或排版元素。

对比、参数、教程等依赖文字的模块改为纯视觉构图表达，不得擅自恢复文字。

产品自身原有的 Logo、按钮文字、包装文字和标识允许保留，但必须忠实复现上传素材，不得改写、翻译、替换或重新设计。

## 产品锁定

所有模块、两种文案模式都必须以用户上传的产品图为唯一产品事实来源。不得改变或虚构：

- 产品类别、轮廓、结构、部件和附件。
- 颜色、材质、纹理、表面处理和比例。
- Logo、按钮、接口、端口、控制区和组件位置。
- 包装、标识及任何可辨认产品细节。

看不清的产品细节应保持简单或不展示，不得猜测补全。场景、背景、光线和非产品装饰可以按模块目标变化，但不得遮挡或改造产品。

## 提示词

新增统一的模块文字策略生成函数：

- 带文案：复用现有 `VISIBLE TEXT` 与文字密度规则。
- 无文案：输出高优先级 `NO ADDED TEXT` 规则，并覆盖模块原始请求中可能包含的标题、参数表、尺寸标签或步骤文字要求。

强化 `buildProductLockPrompt()`，让产品细节锁定独立于模块类型和文案模式。

## 历史与 SEO

- 历史项目保存每张任务的 `includeText`，恢复后重绘继续沿用。
- 旧历史没有字段时默认允许文案，保持向后兼容。
- SEO 标题和 Alt 文案继续生成和显示，它们是页面元数据，不会画入图片，不受本开关影响。

## 测试

前端测试覆盖：

1. 所有默认模块的 `includeText` 为 `true`。
2. 单模块切换只改变目标模块，不改变 `active` 或 `count`。
3. 任务构建正确传递 `includeText`。
4. 带文案提示词保留现有文字规则。
5. 无文案提示词禁止所有新增文字，并允许仅忠实保留产品原有标识。
6. 两种模式都包含强化产品锁定规则。
7. 历史快照保存字段，旧历史缺失字段时按 `true` 恢复。

## 范围

本次只修改详情页模块卡片、图片任务提示词和详情页项目历史字段，不改变后端 AI 路由、不进行生成后图片擦字，也不修改其他功能的文案生成。
