# Trends 查询词准备

用户已确认：系统准备查询词、中文释义和依据，用户确认或修改后采集；优先复用同一商品同一市场已确认的查询，两个时间窗口使用同一词。资料不足明确提示，无数据不等于无需求，不自动换词重试。

实现选择：复用现有主应用 callAI(text) 与原 Trends 入队链路。新前端服务从当前商品页快照提供有界文本给 AI，校验建议的原文引用。查询词建议不属于需求证据。已确认查询及释义存于浏览器本地，并绑定项目、商品、身份版本、商品 URL 和市场；仍可从当前身份的趋势证据恢复查询。请求仅提交现有 query 字段，不改后端门槛。

其他方案：直接填品牌名或广告发现词无法保证描述具体商品；新增一套后端采集器重复现有实现，且不能解决用户不知道查询什么的问题。

交互：打开确认窗口后先复用本地确认词/当前身份趋势记录，否则自动生成一个推荐主词、最多两个备选；显示中文释义、原文依据和待确认说明。用户改字后保留其输入，不让异步建议覆盖。失败任务的常规重试明确沿用并展示原查询词；“使用其他查询词”才打开重新准备流程，且在确认前不入队。初次准备失败时允许手动输入、再次准备或返回补充商品资料。只有用户提交后入队；成功后记住词。结果不确定时保持原命令身份和输入，不自动重新提交。打开页面进行验收不得调用真实收费 AI 或提交真实证据。

边界：商品/市场切换或资料版本变化后，迟到建议不得应用；复用历史词需检查身份、市场及可用查询长度，冲突词要求选择；AI 失败不写虚构替代词/释义。旧手动工作流继续可用。仅更新本机正式客户端，保留数据与回退，不重制客户 DMG。
