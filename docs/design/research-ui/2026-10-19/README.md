## 流程与业务约束

- 设计主线：创建研究 → 准备/审核词 → 搜索与浏览 → 快筛/核实商品 → 广告粗筛 → 需求、竞争、漏斗/扩词 → 成本与风险 → 证据评分 → 人工决定 → 符合条件时测试 → 复盘/报告。
- 不是每个商品都必须测试。观察、淘汰分支可直接做研究复盘，不得伪造测试结果。
- 商品身份确认、广告粗筛、渠道证据、成本、评分与决定分别成立，不能因保存了来源或完成采集而自动通过。
- 广告年龄不等于连续投放；粗筛仍需当前活跃及足够的独立活跃创意。
- 评分以现有后端五维、满分25为准。缺证据时不展示假分；旧评分不能支撑当前决定。
- 未知成本不填0；情景估算不能当作实际营收；域名流量不能当作具体商品销量。
- 统一设置负责接口和能力绑定。研究页不再出现另一套AI或集成配置。
- 扩词重新审核；保存计划不投放；批准同步只写入明确批准的版本。
- 既有同款关联、重复档案合并、历史/版本、提交回执、报价历史等入口保留；不得通过精简设计删除功能。

## 组件与状态设计说明

主页面用单一全局导航。项目切换放在页头；搜索词、候选商品等在工作区内切换。表单采用就地编辑或右侧抽屉，避免每改一项就跳到空白新页。低频入口折叠收纳，不代表删去。

主操作使用蓝色；进行中展示当前动作；待人工确认、证据不足、来源受限使用文字＋状态色；“暂无”不使用成功状态。失败保留成功结果、说明原因并提供具体下一步。测试结果与财务数字必须由程序计算，设计图片中的静态数字不得作为实现公式。

本轮是页面级视觉草案，并非所有子表单、所有Tab及所有异常分支的逐帧交互规格。例如第06页同款/合并、第10页辅助调查、第11页承运商与情景估算等均保留入口，后续实施前还需按实际字段展开细化；删除项目必须使用独立确认，不能用无说明菜单动作直接删除。

## 实施前需要统一的细节

1. 图中的简化页头进度条仍存在文案、数量和辅助页显示差异。落地时统一映射现有 `services/journey.mjs` 四组与10步骤：找到并核实商品（identification/coarse）、判断需求与竞争（expansion/channels/funnel）、算收益与风险（economics/score）、作决定与验证（decision/test/review）。不增加或删除业务状态；工具/设置/历史等辅助页不显示商品步骤进度。创建项目和搜索入口单独处理。
2. 1440px桌面草图不代表小窗适配已验证。窄屏采用列表与详情切换，保留选中项、滚动与素材缓存；不能强塞四列，也不能重新引入两套导航。
3. 手绘式生成图可能仍有细字、日期、图标和段落差异，最终文案与控件取实际数据、可访问性规范和后端规则。概念图不是逐像素实现验收标准。
4. 第11页已修正已填写成本合计为15.56美元；第17页已统一25分制；第07页已校正勾选与2/3统计一致；第15页已校正测试阶段位置。所有这些依旧是示例，不是实际业务计算。
5. 图中批量选择、同屏编辑、日期筛选等是交互提案，是否已有接口支持需实施前逐项核验；不以图片暗示已经上线。
