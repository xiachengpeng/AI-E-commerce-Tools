日期：2026-10-18。目标：重新从首次进入走到形成可解释的研究结论，不以页面美化或测试通过代替用户体验验收。

## 结论

普通 Chrome 中，“新建研究→添加并审核词→真实搜索→查看素材→核对商品→保留深挖→检查缺口→观察决定→研究复盘→下载报告”的观察分支已经走通。仍不能认定整个产品好用或所有业务分支通过：内置浏览器出现请求中断；跨页面状态、操作顺序和技术语言仍增加理解成本。

本轮未改业务代码。只在独立项目“用户流程复测-20261018”内新增研究数据；未修改美国火花塞市场等原项目。未投放、未发布、未写飞书。未虚构供应商报价、独立创意或成交结果。

## 范围与真实样本

研究美国市场 spark plug gap tool。执行一次 Meta 精确短语 UI 搜索及一次自动核对批次，批次衔接两次本地商品页读取；未使用 Firecrawl，未重复运行收费任务。未执行 AI 初始词、方向生成或扩词。

搜索得到3条广告、2条商品线索。Universal Spark Plug Gap Tool 绑定2条不同广告 ID，但文案相同，不能直接认定为两个独立创意。另一条 Coozy land 商品页重定向后仍保留人工复核。

## 按优先级处理的问题

### P1：内置浏览器无法完成创建和刷新

**事实**：创建和刷新显示本机研究服务连接问题，浏览器诊断为 Fetch ERR_ABORTED；本机服务仍在运行，读取会话返回200，失败创建后检查没有同名项目。随后普通 Chrome 创建成功。

**影响**：用户在当前主要入口无法开始，难以判断是否保存，更不敢重试。

**建议**：先定位内置浏览器中请求被终止的来源与时序；保留当前不确定提交回执和输入，补充按请求标识查询保存结果的恢复入口。不要靠反复提交或降低安全校验规避。

**待验证**：具体是浏览器桥接、页面生命周期还是请求实现导致中断，当前证据不能归因于后端停机。

证据：[创建失败](03-create-connection-failure.png)、[Chrome创建成功](04-created-chrome.png)。

### P2：AI 匹配被表达成人工已确认

探索页“相关性已确认 / 商品相关性：已确认”与任务页“AI 已匹配”不一致。本轮没有执行人工确认具体商品。

应统一成“AI判断相关，待你确认”，并用独立字段展示采集、AI判断、人工核实。核对成功不等于所有事实确认。

证据：[商品图与状态文案](09-product-image-and-ai-wording.png)。

### P2：连续操作仍要求用户记住顺序并跳页

添加词→保存→审核→搜索→任务页再次确认；自动核对又跳任务页确认，再回探索。用户需反复确认当前对象、服务和结果。

建议让“审核并搜索”在原研究上下文完成，提交前展示词、市场、数量范围及费用提示；任务进度留在当前商品/词附近。人工审核和可能收费的确认不能省掉，但可以集中一次完成。不要擅自连续重跑有费用的任务。

证据：[任务确认](05-search-confirmation.png)、[任务日志](06-task-log.png)。

### P2：顶部回执不跟随任务结果更新

搜索与核对已完成时，顶部仍曾显示“已保存执行请求；尚未确认取得结果”。这会与完成状态、实际素材互相矛盾。

建议按当前任务身份更新为“完成：3条广告、2个商品”，失败则说明失败步骤、已有成功结果及下一步。请求已保存、任务运行中、已取得结果要用同一套状态来源。

证据：[搜索结果](07-search-results-media.png)、[核对完成](08-verification-complete.png)。

### P2：评分反馈仍暴露内部数据结构

实际结果含 coarse_screen、trends_query_match、economics 等键；产物还直接展示算法名、版本以及原始审计字段。人工决定/复盘产物默认展示 id、score_id、operator。

建议将正常结果展示为业务缺口及“去补充”按钮，把标识与版本移入审计详情。现有中文缺口列表可复用，不应让结果文案再退回英文键名。

证据：[评分阻止及原始键名](13-score-blocked.png)。

### P2：判断需求时首先看到扩词与冗长网页全文

点击“2.判断需求与竞争”首先进入沿线索扩词，下方直接展开带导航、购物车、支付问答等噪声的长商品原文。真正的竞争、趋势及漏斗任务还需自行寻找。

建议该组先给出“已有证据→尚不确定→建议下一步”的概览，再提供扩词、趋势、竞争、表达核对的明确子入口。原文按关键段落折叠保留，不得用未经核实的网页宣传作为经营事实。

### P2：观察状态缺少统一的解释

人工决定已经是观察，下载报告漏斗仍显示“保留1、观察0”。合理推断这是初筛处置与最终人工决定的不同统计，而非已经证实的数据错误，但当前报告没有就近解释，用户会以为观察未保存。

建议明确分成“线索筛选去向”和“最终经营决定”，或给出统计口径说明；不要直接改统计去掩盖不同业务含义。

### P3：来源“可用”和自动接口能力含混

工具页面部分渠道标为可用，同时说明尚未连接自动接口。需要明确区分“可手动记录”与“可自动采集”，把密钥配置留在设置内，主流程只提供可理解的能力说明。

### P3：已观察值与人工确认值割裂

粗筛摘要显示年龄/当前状态未知，但表单已带入101天和两条当前活跃广告。业务上保守处理正确，表达上像数据遗失。

建议摘要并排展示“采集观察：101天/当前活跃；人工：待核实”，只计算已核实的独立创意。补充不足时应能直接继续搜素材或先观察。

证据：[保留后页面](10-retained-next-task.png)、[粗筛带入](11-coarse-prefill.png)。

### P3：报告项目筛选范围不一致

上部选中本轮项目，下部仍有全部项目同名下载按钮，用户须向下找新项目。下载本身成功，自动化下载监听超时不等于产品下载失败；落盘文件已另行验证，保存链接再次点击会形成第二份副本。

建议只展示当前项目的报告，其他项目置于明确的项目切换入口；生成与已下载状态分开，不将生成成功表述成已保存到磁盘。

证据：[结论页实际画面](14-observe-review-complete.png)。

## 保留的有效改进

- 当前任务导航与业务分组比十项平铺更容易进入；保留商品后自动继续到粗筛。
- 任务日志、结果轮询、广告视频与商品主图本轮真实可用。
- 独立性不自动确认；重定向商品保留人工检查。
- 成本、物流与认证未知不会被默认当成0、低风险或不需要认证。
- 证据不足不会生成假分数；观察分支能完成复盘，不强迫造测试结果。
- 汇总页已经展示决定理由和下一步，而不仅是分数。

## 建议下一轮改动顺序与验收

1. 先修内置浏览器提交/刷新阻断。验收：新项目只创建一份；断线后可查询结果；失败输入保留，成功恢复不重复收费。
2. 统一 AI/人工/观察状态及任务回执。验收：同一商品在探索、任务、报告语义一致；任务完成无旧未确认提示。
3. 合并词审核与搜索的连续路径，保留范围/费用确认。验收：用户不离开上下文即可看执行进度、结果及可操作失败原因。
4. 调整需求组入口和全文信息层级。验收：首次进入即可知道要判断什么、目前缺什么；原始证据仍可追溯。
5. 统一报告筛选、统计口径和业务语言。验收：当前项目下载入口唯一明确，评分失败全部中文可读，观察统计与决定口径解释清楚。

## 验证边界

本轮走通的是**证据不足→观察→研究复盘**，没有验证完整有效评分→测试池→批准测试→真实投放结果的正向分支。缺少3个独立活跃创意、趋势、完整漏斗及供应商报价是真实业务前提，不应为通过验收编造。多渠道自动采集、AI扩词、长期任务恢复、移动端及全面无障碍尚未复测。
