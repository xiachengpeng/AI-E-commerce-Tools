# 02 功能融合对照表

日期：2026-10-08。项目根目录、证据等级与当前版本见 [01-项目现状分析](01-项目现状分析.md)。本表是**未来实施建议**，没有发生代码迁移。

## 1. 分类定义与实施顺序

- **A 可以直接融合**：纯计算、无数据库/网络/全局 UI 依赖，主体算法可保留，仅做包路径、请求模型和 UI 包装。A 不表示零修改。
- **B 需要适配**：有业务价值，但必须转换 DTO、权限、事实确认、状态或持久化接口。
- **C 功能重复需整合**：名字相近或共享底层能力；按真实语义合并入口/能力，不能盲目删除一种实现。
- **D 不建议融合**：指表中指定的迁移/替换方式不合理，不代表删掉原功能。
- **E 暂留独立**：技术可集成，但应保留独立进程、存储或外部写入边界。

处理决策（推断）以主项目为核心：保留其 FastAPI、原生 JS、Tailwind、SQLite、历史 API 与现有工具；研究核心保留 PostgreSQL/私有证据，先接口集成。E 可成为统一项目内独立服务，统一项目不要求一个数据库。

## 3. 重复能力的实际质量比较

| 能力 | 更适合的实现 | 理由/限制 |
|---|---|---|
| 多提供商 AI 路由 | 主项目 | text/image、Gemini/Vertex/OpenAI 适配与运行时 binding；SOP 的强类型输出/引文规则仍需保留 |
| 研究证据与未知态 | SOP | 原件 hash、source passage、身份版本、引文核验与 Required/Unknown；不能降低为普通营销推断 |
| 商品评分 | 保留两种 | 主商业机会分适于策略；SOP 有资格门槛适于研究决策。两者质量不以分数高低判断 |
| 图像/PDP/托管 | 主项目 | 现有交互、导出、多目标驱动齐全；SOP 无等价模块 |
| 持久研究状态/恢复 | SOP | 事件、version、command digest、row locks、attempt fencing；移植思想可改善主项目，但不全面重构 |
| 安全页面/URL读取 | 分层复用 SOP 防护思想 | SOP 有针对证据 provenance 的校验；主支持可配置本地目标。不能共享一个无差别 allow_local 标志 |
| 翻译 | 分用途保留提供商 | 阿里云是中文阅读与缓存，主 AI 是多语营销；统一 UI 模式与输出 envelope，不静默替换 |
| 私有密钥写入 | 可借鉴 SOP 原子文件与权限 | fcntl 平台限制、文件明文不等于加密；主数据库方案仍为默认，不直接照搬文件型设置 |

上述“更适合”是基于已读实现的架构推断，不代表本次已测得供应商效果、速度或成本优胜。

## 4. 建议第一个业务闭环

1. 研究项目选国家 → 审核搜索词 → 人工发起采集。
2. 商品 identity/原文证据 → 核对 → 人工确认可以用于营销的事实。
3. 主项目展示“待导入营销档案”预览，逐项接受且保留用户已输入内容。
4. 使用主项目现有 Listing/广告/详情生成与交付。
5. 人工关联生产成果到 SOP 测试计划，手动记录并确认真实测试结果。

任何采集失败、来源未知、过期或 identity_revision 变化，都不能变成确认事实；研究引用保留，营销草稿不自动销毁，UI 提示事实需复核。
