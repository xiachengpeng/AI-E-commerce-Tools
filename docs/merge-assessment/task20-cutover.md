## Tool contract

Use `PYTHONPATH=backend:. python -m scripts.full_merge.cutover <private-plan.json>` for default dry-run. Explicit `--execute` is the mutation boundary. The private plan selects `local_readonly` first and `local_active` only after successful read verification. All other plan fields are immutable once the journal exists.

The fsynced private journal records `prepared → source_frozen → verified → local_readonly → local_active`. A lock excludes duplicate local operators. Source fencing is separate: a reviewed, hash-pinned private collector obtains a new nonce-bound live observation before each data move and activation. It checks the complete inventoried writers, disabled auto-restart, in-flight work, dataset/generation, frozen source content digest and freshness. An unreachable source fails closed. A static `source_frozen: true` report is insufficient. The collector and its concrete host inventory are trusted operator inputs and must be reviewed with the plan; the generic tool cannot infer unknown writers.

Independent external snapshot anchors are reverified, real SQLite copies are restored and compared, and candidate provenance must match the source and main anchors. Signed revision-4 ownership and quarantine validation applies before installation and activation. Unknown external outcomes retain their exact resource IDs, attempts and payload hashes. No automatic resubmission, expiry-based release, or provider fallback is introduced.

SQLite files remain at the canonical primary `backend/history.db` path. Symlink or multiply linked primary databases are rejected. Candidate, recovery files and target directories must share a filesystem. All open database handles, including idle connections, are rejected. Checkpointed original DB/WAL/SHM/journal files are moved into a private recovery directory before the candidate is installed. Every data rename has a durable intent and content identity; this is a recoverable group transaction, not an assertion that multiple renames are atomically visible. Keep writers stopped throughout. An explicit startup journal blocks direct backend/launcher startup while the group is incomplete or read-only.

The local read stage uses authenticated ASGI GET checks in process, with no public listener and no worker. The first signed claim occurs before activation publication; main initialization consumes a valid handoff before normal settings/history initialization can change its initial logical hash. Missing research activation remains read-only. A local worker is started only for explicit active local configuration, after API readiness and a consumed signature. The launcher retains ports 9502/9503 and `ThreadingHTTPServer`, starts no research tunnel, and stops only its own children. A child that does not stop within the grace period is reported, not automatically force-killed.

## Recovery

`rollback(plan, preserve_new_writes=True)` reverses preactivation intents and restores the original database/private root. It also handles a power failure after rename but before receipt. New read-only sidecars are preserved separately; old frames cannot be attached to the candidate. Local recovery does not depend on the source still being reachable and never automatically restarts it.

After the durable activation intent, recovery conservatively assumes the first claim may have occurred. It never replaces the current database with an old snapshot. Close writers, hold the maintenance journal, create a fresh independently verified incremental snapshot on every invocation, suspend the published activation, and enter `reconciliation_required`. Code rollback must remain schema-compatible; data/receipt reconciliation and any subsequent ownership transfer are separate operations. No source revival is automatic.
