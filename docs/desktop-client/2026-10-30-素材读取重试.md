# 2026-10-30 素材读取与重试反馈修复

## 原因与边界

本机系统 DNS 将广告素材 CDN 域名解析为 `198.18.0.0/15` 中的代理虚拟地址，`SafeUrlClient` 按现有安全规则拒绝连接。当前保存的视频请求因此快速返回 502；原界面点击后隐藏重试按钮，又立即恢复同一错误文本，用户无法分辨是否执行。

另一个独立问题：视频已经插入后发生播放器错误，点击重试虽然失效缓存，但预览逻辑遇到相同素材 key 直接返回，不会重新请求。

## 修改

- `sourcePreview` 显式重试绕过相同 key 的复用分支，仍使用原项目、关键词、商品、广告及素材序号选择器。
- 重试期间保留禁用的按钮，展示“正在重试读取素材…”及次数；失败、读取成功、播放器准备完成分别反馈。双击只发出一次请求。
- 旧播放器事件、切换来源后的迟到结果及页面销毁不得覆盖当前预览；媒体租约仍按原生命周期释放。
- 本机现有私有研究业务配置的 `public_dns` 从 `system` 改为已有的 `google` 方案；其他客户端默认值未改。没有放行私有/虚拟 IP，也没有取消逐跳 URL 校验、DNS 地址绑定或 TLS 验证。

## 验证

- 先新增回归测试，复现按钮加载态缺失、失败视频同 key 早退及旧视频事件覆盖加载提示；修复后通过。
- 完整前端串行测试：978 passed；JS 语法与改动文件 `git diff --check` 通过。
- 素材下载及公共 DNS 安全测试：5 passed，使用隔离 SQLite 和 `--asyncio-mode=auto`，包括混合公网/私网 DNS 回答拒绝、原来源绑定与私网重定向拒绝。
- 同一已保存视频：修改前正式接口 502；公共 DNS 验证读取成功；本机正式客户端更新后接口 200、`video/mp4`、1,095,288 字节。
- 正式客户端原广告预览显示视频首帧、播放控件与 30 秒时长。保留原正式数据目录，数据库 `quick_check=ok`，两把研究密钥哈希未变。
