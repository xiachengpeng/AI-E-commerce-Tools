日期：2026-10-23。平台：本机 Apple Silicon Mac。版本：0.2.0 测试候选包；0.2.1 仅作升级演练。

**结论：本机候选验收通过，正式发行门禁未通过。** 没有替换开发者自用应用或复制其业务数据；客户必须自行配置账户。自用应用文件及私有配置哈希、数据库各表记录数与验收前基线一致，已恢复原自用工作台（9 个研究项目）。本文不是另一台 Mac 的验收结论。

## 实际实现

| 能力 | 实现与限制 |
| --- | --- |
| 独立应用 | `AI E-commerce Tools Customer.app`；固定 bundle ID `local.ai-ecommerce-tools.customer`，与自用版分离 |
| 空数据安装 | 专门的客户启动入口创建空库、研究 schema v4、独立 dataset ID、证据命名空间和两把随机签名密钥 |
| 所有权 | 新增 `fresh_install` 签名授权，不伪造迁移源冻结证明；保留原 HMAC、候选哈希、首次消费、账本代次和后续写入校验 |
| 首次配置 | 复用原设置里的 AI、外部服务及多套密钥；引导可在 AI 模型设置里重新打开；不预置个人品牌画像 |
| 后台策略 | 初始暂停；需保存并确认研究业务规则、确认服务费用后才可设置下次启动启用。飞书观察轮询只读，不扩大有限执行授权 |
| 版本更新 | 手动替换应用；稳定数据路径；不同版本启动前冷备份整个工作区以及浏览器本地业务存储；降级拒绝 |
| 发布 | 仅开发签名候选包；无自动下载更新、无公开发布、无正式签名/公证声明 |

核心文件：`backend/services/customer_distribution.py`、`backend/routes/customer_setup.py`、`backend/services/research_activation.py`、`backend/desktop_entry.py`、`desktop/main.cjs`、`desktop/distribution.cjs`、`frontend/js/customer_setup.mjs`、`frontend/css/customer_setup.css`、`scripts/desktop/build_customer.py`、`scripts/desktop/verify_customer.py`、`desktop/build/customer-package.cjs`。

## 实测结果

1. 全新客户目录首次启动成功。实际 SQLite 检查：研究项目、AI 线路、存储账户、集成凭据均为 0；后台 paused、飞书 polling false。没有 `.env` 预置文件。
2. 原生客户端能够显示首次引导、确认并保存研究规则、完成引导，再从设置打开。未勾选费用确认，不允许开启后台。
3. 原生创建一个明确标记的软件验收研究项目；仅保存本机记录，未采集、未使用 AI、未同步飞书。原开发者的研究项目没有导入到客户目录。
4. 0.2.0 正常退出重启：密钥、研究规则、引导完成状态哈希均保持一致。
5. 在原生客户界面将字号设置为 18px。正常退出旧版后打开 0.2.1 演练版，旧版备份自动生成。项目数仍为 1；业务配置和两把密钥哈希一致；主库和备份库 `PRAGMA integrity_check` 均为 `ok`。
6. 浏览器配置备份包含实际 `Local Storage/leveldb`。升级后的原生设置仍显示 18px。
7. 正常关闭演练版，将较新工作区和 profile 安全归档后，成套恢复 0.2.0 备份及其浏览器业务存储。重新打开旧应用成功，仍有 1 个项目、正确密钥和业务规则，原生设置仍显示 18px。未覆盖正在运行的数据。
8. 客户验收数据始终在独立目录，未装入 DMG。可分发的应用资源不包含运行数据。

## 明确保留的边界

- 正式门禁实际返回 `official-signature-missing`、`notarization-missing`、`gatekeeper-not-accepted`。这是候选状态，不是正式发布完成。当前电脑没有可用 Developer ID 签名身份。
- 第二台 Mac 的首次安装、下载后的隔离属性及系统接受情况尚未验证；不指导客户关闭系统保护来绕过。
- 未重新调用收费 AI/采集服务，未进行云端上传或飞书写入；本轮外部业务提交为 0。连接配置和眼睛/多账户能力沿用此前已交付实现。
- 本版不自动升级研究 schema。后续研究 schema 变更须有独立迁移、升级与回滚演练，不能只改版本号。
- 自动在线更新、Windows、Intel Mac、服务器多用户部署、商业授权管理不在本轮交付范围。

## 决策和回滚

保留已有未提交源码，在当前工作区制作候选，没有提交或重置工作区；代价是审查需使用本轮私有 `source-before` 基线区分历史改动。客户分发使用独立身份，不能直接接管自用数据。正式签名与第二台 Mac 验证完成前保持候选门禁，防止将本机测试扩大为发行承诺。审查未留下延期的小问题。

应用回滚、用户数据位置和客户操作流程见[客户版安装与更新指南](客户版安装与更新指南.md)。源码变更前基线、构建日志、原生演练资料保存在发行方的私有收尾目录；不把私有备份、密钥或测试工作区发送给客户。
