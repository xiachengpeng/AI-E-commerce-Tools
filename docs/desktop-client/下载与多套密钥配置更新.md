## 怎样使用

### 下载尺寸重绘 ZIP

图片处理完成后点击“下载 ZIP”。按钮会显示“正在准备 ZIP…”，客户端弹出系统保存窗口，选择位置并保存；浏览器使用其正常下载方式。压缩包保留已有图片及 `manifest.json`。打包失败、服务不可用或返回错误时给出提示，页面和已有结果保留。

全部图片本来就符合目标比例时，先点“准备原图 ZIP”，再点“下载 ZIP”，不会执行 AI 重绘。

### 查看已保存的密钥

设置 → 外部服务与存储集成 → 选择服务。密钥关闭状态显示缩略值；点击右侧小眼睛显示完整值，再点击收起。读取已保存密钥不等于修改密钥；输入留空后保存继续保留原值。

完整值只在明确点击时从本机受保护接口读取，普通配置列表仍脱敏；关闭、换服务、离开接口编辑器或页面隐藏时收起本次展开值。未保存的用户输入仍按草稿处理，放弃更改才清除。完整密钥不写入研究草稿、业务状态或 localStorage。既有 AI 线路、竞品 Firecrawl 和存储密钥眼睛继续使用统一工具；补上本机会话、来源检查与禁止缓存，收起后不把完整值放在 DOM dataset 缓存。

### 保存和选择多套外部服务凭据

适用服务：Apify、SerpApi、阿里云翻译、飞书，以及 Firecrawl 的选品研究用途。

1. 原有账号显示为“原有配置 · 使用中”，无需重填。
2. 点“新增配置”，填写名称、这套账号的凭据与调用上限（如有），点“保存配置”。新配置不会继承其他账号的密钥，也不会自动启用。
3. 在“已保存配置”下拉框中选择配置，只会读取和展示它。
4. 核对后点“使用此配置”，后续操作才读取该账号；页面明确显示当前使用的名称。
5. 如需改回，选择原有配置，再点“使用此配置”。有未保存修改时先保存，或点“放弃未保存更改”。

“测试连接”测试当前所选的已保存配置，不会顺便切换正在使用的账号。不同配置分别保留测试所需的凭据；不自动轮换、不因失败自动换账号、不启动采集或飞书写入，也不修改原有预算流水。每个服务最多保存20套，配置名称须唯一且不超过60字符。

飞书的 App ID、App Secret、Base Token 作为一整套保存，阿里云 ID/Secret 同样成组，避免只换一个 Key 后凭据混搭。API 既有业务权限、额度和不确定提交保护保留；执行中的多个独立操作可能在不同时间读取配置，切换前应确认原任务状态。

WordPress 与 Shopify 原有多站点/多店铺添加和选择入口保留，不再另造一套图床配置。竞品 Firecrawl 的独立服务地址及用途配置、原 R2 编辑方式本轮没有重构；不能将研究用途选择器理解为所有用途都已共用账号。

## 修改依据与实现

ZIP 旧实现把 `window.location.href` 指向9503，桌面窗口只允许9502导航，因此被拦截且没有用户提示。改为一次读取 ZIP → 本地 Blob 下载，校验 HTTP 状态、媒体类型和非空文件，保留页面并防重复点击；没有放宽桌面导航策略。

命名账号沿用已准备的 SQLite `integration_settings` 表：当前生效凭据仍是原扁平记录，命名配置目录使用内部保留用途后缀。新增、编辑与切换在 SQLite 事务中完成；无表迁移、无启动批量写入。旧配置只有只读虚拟“原有配置”，用户保存或新增时才建立目录。读取目录的用途被公共接口拒绝，防止绕过脱敏。修改/启用/明文读取使用版本核对，旧窗口不能覆盖新版本。

API 和 worker 继续读取原扁平当前记录，因此无需改业务调用链；旧版应用回滚后编辑该记录，再次升级时它仍是权威，读取时纠正目录快照、不写迁移。连接测试取得所选配置的版本快照，不读取未保存草稿。
