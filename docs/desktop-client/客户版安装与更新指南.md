适用：Apple Silicon（M 系列）Mac 客户版 0.2.0。当前制品标记为**测试候选包**，不能作为正式签名发行版向客户公开推广。

截至2026-10-26：已有客户0.2.0测试包未随10月24—26日研究界面与流程修复重建。自用客户端更新不等于客户安装包更新；下一次交付需从已验收源码重新构建、执行客户隔离及升级校验，再按正式发行要求签名、公证。不要将旧包描述为包含最新功能。

## 首次交付前

发行方应完成 Developer ID 正式签名、Apple 公证及另一台 Mac 的首次安装验收。当前电脑没有可用的 Developer ID 签名身份，本地开发签名校验通过也不能替代这些步骤。不要让不懂技术的客户通过关闭系统安全机制安装。

正式分发规则以 [Apple 官方说明](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) 为准。正式发布门禁可运行 `scripts/desktop/verify_customer.py --official` 检查签名、已装订公证票据及 Gatekeeper 接受情况。

## 安装

1. 收到正式签名版本及对应 SHA256 校验值后，打开 DMG。
2. 将 `AI E-commerce Tools Customer.app` 拖到“应用程序”。不要直接从磁盘映像长期运行。
3. 从“应用程序”打开客户版。第一次会创建自己的工作区并显示使用引导。
4. 在“配置 AI 模型”中添加自己的服务商账户，设置文字、图像模型并绑定用途，按需测试连接。
5. 在“配置外部服务与存储”中配置自己需要的 Apify、SerpApi、Firecrawl、翻译、飞书及存储账户。无需的服务可留空。密钥留空保存会保留原值；可添加多套账户并明确选择使用哪套。
6. 返回“设置 → AI 模型 → 首次使用与后台设置”，按实际业务确认研究市场、费用估算与每日上限。示例值不是对真实费用、利润或市场的保证。
7. 后台默认暂停。需要处理研究采集任务时，确认费用提示后选择“下次启动时开启后台”，从应用菜单正常退出，再重新打开。
8. 飞书观察轮询只读取触发信息，不自动执行或写回；自动执行仍受现有有限范围授权与调用预算保护。

端口 9502、9503 被旧浏览器服务或另一版客户端占用时，先正常退出旧服务再打开。客户端不会结束其他程序。

## 数据在哪里

- 客户业务工作区：`~/Library/Application Support/AI E-commerce Tools Customer/workspace`
- 客户浏览器界面数据：同级 `profile` 文件夹。
- 升级备份：同级 `backups` 文件夹。

客户版与开发者自用版使用不同目录。安装包不应附带数据库、密钥、历史素材、个人品牌画像、浏览器草稿或迁移授权。客户自己的密钥和签名材料首次运行后才在本机保存。备份含有这些敏感资料，只能由客户私下保管。

数据是本地保存；调用 AI、采集、翻译、云存储及飞书功能时，必要内容会发送给客户配置的相应服务商。

## 后续如何更新

第一版采用手动更新，不会自动下载或覆盖应用。

1. 发行方修改同一套源码、运行回归及纯净包审计，每次提高三段版本号，例如 0.2.0 → 0.2.1。
2. 保持应用名、bundle ID `local.ai-ecommerce-tools.customer` 及上述数据目录不变。重新制作纯净包，正式签名、公证，附版本说明和 SHA256。
3. 客户先检查正在运行的任务，必要时记录尚未确认结果的收费操作；从应用菜单正常退出客户端。
4. 打开新版 DMG，把新版应用拖到“应用程序”覆盖**客户版应用本体**。不要删除 Application Support 内的数据目录。
5. 打开新版，启动前会为旧版本工作区和本地浏览器业务存储生成完整私有备份。备份失败、仍有进程占用、所有权损坏或版本降级时拒绝继续，保留原数据。
6. 原项目、密钥、历史、图片及设置继续保留。业务规则或后台开关变更后需正常退出重开。

本版不会自动迁移研究数据库 schema。未来版本需要 schema 变更时，发行方必须另行实现、演练并发布迁移和回滚方案，不能仅提高版本号。

## 出现问题与回滚

先保留应用、工作区及备份，不要重复提交结果不明的采集、生成或上传。

- 当前版本的界面或配置问题：记录版本和现象，提供已脱敏的日志给维护者；不要发送 API 密钥或整个数据目录。
- 无法启动：正常退出其他占用端口的实例后重试；仍失败请维护者核对候选报告和备份。
- 需要退回旧版：应用与该旧版对应的工作区备份应成套恢复；同一版本备份内的 `browser-profile` 对应上级 `profile` 的业务存储。先停止所有客户端/服务，将当前数据另存为安全副本，再由维护者在独立位置验证恢复后替换。禁止把旧数据库直接覆盖在运行中的新版上。
- 启动旧应用直接读取较新数据会被拒绝。这是降级保护，避免旧代码破坏新数据。
