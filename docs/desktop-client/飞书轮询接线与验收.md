## 开关关系

| 配置 | 行为 |
| --- | --- |
| `enabled=false`或`worker_mode=paused` | 不启动执行worker，也不进行轮询 |
| 有效激活/已消费账本，active，未开轮询 | 原生动作、原legacy消费和用户已请求的摘要同步可以执行；不读取飞书触发视图 |
| 有效激活/已消费账本，active，`feishu_polling_enabled=true` | 在同一owner中增加飞书触发轮询；符合原触发规则的记录按原幂等与预算机制入队 |

`worker_mode`和轮询开关需要重启所属worker后生效；本次没有增加会自动执行任务的设置保存动作。保持暂停的维护配置示意：

```json
{"enabled":true,"worker_mode":"paused","feishu_polling_enabled":false}
```

这只是字段示意，不能用它覆盖真实配置文件；真实文件还包含现有数据根、业务配置及交接信息。不能删除这些字段，也不能绕开签名与账本门禁。

## 时序、故障与可观测性

每轮完成（成功或失败）后等待显式业务配置中的`poll_seconds`，当前为60秒；不会重叠轮询或在失败时高速重试。一次轮询有60秒默认总超时，取消直接向上传播，正常停机可以结束正在读取的轮询。HTTP读取的原适配器行为和记录入队幂等机制保留。

轮询错误不向日志输出异常正文、凭据、记录或上游响应。结果写入已有`runtime_health`表：仅保留`feishu_poll_ok`或`feishu_poll_failed`之一及UTC时间。失败后下轮可恢复；若本地状态写入自身失败，向上抛出并停止所属worker，避免伪报健康。

这些行是**最近一次轮询的历史状态**，不是worker仍存活的证明；应同时核对`workbench_worker`心跳的新鲜度和实际所属进程。该记录供维护核验，本轮未增加设置页实时日志的跨进程转发，不能宣称它已显示在设置页SSE中。

重复触发同一输入版本继续复用原JobRepository幂等键。回归覆盖已是needs_human的同一任务再轮询时整行及日预算不变；输入发生新变化仍按原业务规则处理，不能据此宣称所有未来触发都会被禁止。本次没有读取/消费旧触发视图，也没有重试实际9条人工记录。

## 打包自检

`backend/desktop_entry.py --mode verify-polling`只对SQLite只读备份生成的临时副本执行。使用假operator模拟一次读取失败和一次成功，不创建飞书/AI/Apify客户端，不实例化真实队列消费。临时数据根位于系统临时目录，仍经过现有offline路径约束与同一worker锁。

自检同时确认：第二个owner被拒绝；成功状态覆盖失败状态；停止后worker心跳被清理，循环可取消。输出中`external_calls=0`、`production_worker_started=false`。原库和研究证据不写入。该离线自检不代替持续联网运行观察。

## 启用与回退原则

1. 先备份当前客户端数据和配置，核对签名、账本、现有触发记录与预算；不能直接恢复旧快照覆盖用户新编辑。
2. 明确是否处理飞书现存3条触发记录，以及运行时长、允许的调用种类和费用范围；先前单次验收仅花费$0.02255，不代表允许按内部估算上限无限执行。
3. 正常退出客户端；只修改现有私有配置中需要的开关，保持其他字段；再启动客户端，核对唯一worker与轮询状态。
4. 暂停时先把配置恢复paused，再正常退出并重启；只改磁盘文件不会取消已运行的worker。未知外部结果按已有run/记录身份核对，不创建替代任务。
5. 代码回退优先恢复上一应用包，保持当前数据库；本次未改schema。仍须先暂停并结束所属进程，不在原、新应用间并行运行。
